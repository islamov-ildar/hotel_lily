# Отель «Лилия» — Vue + Vite SSG

Одностраничный сайт https://hotel-lily.ru. Главная генерируется в готовый HTML; Vue подключает меню, галереи, модальные окна и обновляет цены.

## Запуск и сборка

Нужен Node.js 22 LTS или новее и доступ к публичному REST API Firebase.

```sh
npm ci
npm run dev
```

Production:

```sh
npm run build
```

Команда оптимизирует фотографии в WebP и шрифты в WOFF2, проверяет TypeScript, получает цены из Firebase, генерирует HTML, административные оболочки, sitemap.xml и robots.txt, затем проверяет результат. Все готовые файлы находятся в `dist/`. Сгенерированные изображения и шрифты в `src/assets/generated/` не хранятся в Git и создаются автоматически.

`npm run build-only` выполняет ту же генерацию без проверки TypeScript. `npm run verify-build` повторяет проверки существующего `dist`.

Основной домен задан в `.env.production`: `VITE_SITE_URL=https://hotel-lily.ru`. При смене домена измените также редиректы в `public/.htaccess` и ожидаемый адрес в `scripts/verify-build.mjs`.

## Цены и Firebase

- При сборке читается `/allData.json` из существующей Firebase Realtime Database. Эти данные включаются в HTML, чтобы посетители и поисковые роботы сразу получали полноценную страницу.
- При **каждом открытии и обновлении главной** браузер повторно запрашивает Firebase через REST с `cache: no-store` и заменяет цены, год, текст и состояние акций. Firebase SDK загружается только в административной части.
- Запрос не задерживает показ готовой страницы. При ошибке сохраняются данные последней сборки и появляется пояснение с просьбой уточнить стоимость при бронировании.
- Изменение цен в админке **не требует пересборки для посетителей с JavaScript**. Исходный HTML и посетители без JavaScript увидят цены последней сборки. Чтобы обновить этот снимок для SEO, периодически пересобирайте сайт.
- Если Firebase недоступен или возвращает некорректные данные при сборке, публикация останавливается. Устаревшие тестовые цены не подставляются.
- Доступ к чтению публичного `allData` должен быть разрешён правилами Firebase. Запись должна оставаться доступной только авторизованным администраторам; наличие скрытой страницы `/admin` не заменяет правила базы.

Автоматическая публикация и изменения правил Firebase в этом проекте не выполнялись.

## Ручная публикация на REG.RU Хост-Лайт / ispmanager

1. Локально выполните `npm ci` и `npm run build`.
2. Включите HTTPS для `hotel-lily.ru` и `www.hotel-lily.ru`, если www используется. Для HTTPS-редиректа сертификат должен покрывать оба имени.
3. Сделайте резервную копию текущих файлов сайта через ispmanager.
4. Загрузите **содержимое** `dist/` в корневой каталог сайта, указанный в настройках домена. Загружать саму папку `dist`, исходники и `node_modules` не нужно.
5. Включите показ скрытых файлов и обязательно перенесите `.htaccess`.
6. Сначала загрузите новые ресурсы `assets/`, затем административные оболочки и `404.html`, в конце — `index.html`, `robots.txt` и `sitemap.xml`. Старые хешированные ресурсы сразу не удаляйте: они могут использоваться уже открытыми страницами. Ручная загрузка не является атомарным переключением версии.
7. Если включено кеширование HTML средствами хостинга, очистите его после публикации.

`.htaccess` задаёт HTTPS и основной домен, адреса `/login` и `/admin`, настоящий 404 без общего SPA-fallback, сжатие и кеширование. Эти правила рассчитаны на Apache 2.4. На REG.RU перед Apache может работать Nginx: проверьте, что он передаёт нужные запросы и не переопределяет заголовки. При HTTP 500 проверьте журнал ошибок и допустимость директив `Options`/модулей у поддержки; не заменяйте все ошибки перенаправлением на главную.

После загрузки проверьте:

- `https://hotel-lily.ru/` — HTML содержит название, описания номеров и цены даже с отключённым JavaScript;
- при обновлении страницы в Network есть один запрос `allData.json`, актуальные цены появляются и на телефоне, и на десктопе;
- `/login` и `/admin` открываются по прямой ссылке, неавторизованного пользователя админка перенаправляет;
- случайный несуществующий адрес возвращает **HTTP 404**, а не 200;
- HTTP и www перенаправляются на `https://hotel-lily.ru/` с сохранением пути;
- ресурсы из `assets/` доступны; HTML не кешируется надолго;
- sitemap содержит только главную. Добавьте sitemap в Яндекс Вебмастер и Google Search Console.

Node.js, PHP, MySQL и постоянный серверный процесс на хостинге не нужны. Firebase Auth/Database продолжают работать как внешние сервисы.

## Видео

В галерее используется оптимизированный H.264/AAC MP4 (`src/assets/videos/hotel-lily.mp4`, около 3,1 МиБ вместо 5,5 МиБ) с метаданными в начале файла и WebP-постером. Исходник сохранён в `src/assets/images/carousel/about/`.

Фоновая загрузка начинается через 2 секунды после события `load`, в свободное время браузера, с низким приоритетом. При экономии трафика, соединении 2G/3G или скрытой вкладке она не запускается. Полностью загруженный файл используется напрямую через Blob URL и не скачивается повторно для воспроизведения. Если пользователь открыл ролик раньше, фоновая загрузка отменяется, плеер начинает обычное потоковое воспроизведение. На хостинге нужно проверить поддержку HTTP Range (ответ 206), чтобы перемотка и потоковая загрузка работали корректно.

Когда видеослайд виден хотя бы на 25%, ролик запускается автоматически без звука. При уходе из видимой области, переключении слайда или скрытии вкладки воспроизведение приостанавливается. При возвращении в видимую область воспроизведение продолжается; нативные элементы управления звуком и паузой сохраняются.

После успешного сохранения цен уведомление отображается 5 секунд, затем плавно скрывается за 400 мс; ошибки остаются видимыми. При повторном сохранении предыдущий таймер отменяется.

## Браузерные проверки

После сборки:

```sh
npx playwright install chromium
npm run test:e2e
```

Можно использовать установленный Chrome: `CHROMIUM_PATH="/path/to/chrome" npm run test:e2e`.

Тесты используют локальный статический сервер и подменяют только чтение цен: проверяют HTML без JavaScript, обновление цен при каждом reload, ошибку Firebase, мобильную таблицу, отсутствие Firebase SDK на главной, прямой вход в админку и HTTP 404. Они не записывают данные в Firebase. Локальный сервер не исполняет `.htaccess`: редиректы и заголовки нужно дополнительно проверить на REG.RU.
